# `corco-installer` — the client bootstrap

Guidance for any agent working in this repository.

## What this repo is

The bootstrap a customer runs in Google Cloud Shell: `setup.sh` onboards and `teardown.sh` removes, and `TUTORIAL.md` and `TEARDOWN.md` are the Cloud Shell tutorials that walk the customer through each. `setup.sh` and `TUTORIAL.md` are written here; `teardown.sh` and `TEARDOWN.md` are copies of `corco-platform` files (see Teardown below). The platform itself is built and released from `corco-platform`.
This is the estate's one public repository (`corcoai/corco-installer`).

## Teardown: vendored copies, never edited here

- **`teardown.sh` and `TEARDOWN.md` are byte-identical copies of `corco-platform`'s `deployment/scripts/teardown.sh` and `deployment/docs/TEARDOWN_TUTORIAL.md`.** `corco-platform` owns both. The teardown button runs `./teardown.sh` from a fresh clone of this repository; the release tarball carries the same script as `deployment/scripts/teardown.sh`, and the script finds the deployment files from its own path, so one script serves both routes.
- **`teardown.provenance.json` records the source commit and the sha256 of each copy.** **Never edit either file here.** `testing/test-teardown-provenance.py` fails on a copy edited in place, and `corco-platform`'s `testing/test-installer-teardown-copy.py` fails when a copy differs from its source or the recorded commit.
- **To refresh:** change the file in `corco-platform` and push it to `main`; copy each source over its file here; in the same commit, set each `sha256` and the `source_commit` (the pushed `corco-platform` commit) in `teardown.provenance.json`; run `python3 testing/test-teardown-provenance.py` and `bash testing/test-teardown-token-transport.sh`; push to `main`. Moving `release` is the customer release (below).
- `testing/test-teardown-token-transport.sh` runs the copy alone in an empty directory, the layout of a fresh clone, with fake `gcloud` and `curl`. It proves that both tokens stay out of every command line and are still sent, that a declined confirmation or a failed project probe changes nothing and tells Corco nothing, and that the two modes that keep the project stop in a fresh clone before any effect.

## What customers run: the `release` branch

- **Both Cloud Shell buttons on `setup.corco.ai`, setup and teardown, clone this repository's `release` branch.** The branch is `INSTALLER_BRANCH` in `corco-platform/deployment/functions/setup-landing/main.py`; its default is `release`, and the deployed function sets no override. Live since 2026-09-18 on revision `setup-landing-00033-cuy`.
- **`main` is not live.** A push or merge to `main` reaches no customer.
- **Moving `release` is the customer release**: the commit it points at is what the next customer clones. That makes it a Corco deploy, so it stays a gated deploy under the existing rule: every Corco deploy needs a fresh named go, each time.
- `release` was created on 2026-09-18 at `79eaffd`, the commit `main` held when the setup page was switched, so the switch changed nothing customers run.

## Documentation links

- `testing/corco_tools/` is a vendored, byte-identical copy of corco-tools' documentation-link checker (`check_doc_links.py`, `repo.py`, `__init__.py`), recorded in `testing/corco_tools.provenance.json` — **never edit these files**; the drift test `corco-tools/test_doc_links_installer_copy.py` fails on any change that is not a fresh copy from corco-tools, and the `doc-links` CI job runs the copy with `PYTHONPATH=testing`.
- The pre-commit hook runs the same copy on the index, `python3 -P -m corco_tools.check_doc_links --staged --strict` with `PYTHONPATH=testing`, and refuses a commit whose staged Markdown holds a broken or same-repo relative link. A commit that stages no `.md` and deletes no path never starts Python; a deletion is checked while the index tracks Markdown. When `python3` cannot run the copy (it needs 3.12 or later), the commit is refused, never let through. `testing/test-doc-links-gate.py`, a step of the `doc-links` CI job, drives the real hook with the real copy in a disposable repository.
